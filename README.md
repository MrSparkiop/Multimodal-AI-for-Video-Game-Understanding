# GameSense — Multimodal AI for Video Game Understanding

**Multi-label prediction of video-game genres from a screenshot and a store description.**

**Author:** Blagoy Hristov · Deep Learning final project

GameSense asks one question and answers it with measurements:

> **Does combining visual and textual information improve video-game genre prediction compared
> with using either images or text alone?**

Three systems are trained on the same games, the same 8-genre label space, the same game-level
split, the same loss, the same optimiser and the same threshold-selection procedure. The only
thing that differs is the input modality.

| | |
|---|---|
| **Task** | multi-label classification — 8 genres, **not** mutually exclusive |
| **Model A** | ImageNet-pretrained **ResNet18** over one screenshot |
| **Model B** | pretrained **DistilBERT** over the store description |
| **Model C** | **late fusion** — both embeddings concatenated → MLP |
| **Data** | Steam Games Dataset (MIT) + screenshots from Valve's public CDN |
| **Deliverables** | Python package · CLI pipeline · research notebook · Streamlit app · 219 tests |

> **Headline result.** Text carries most of the signal, and fusion adds a small but consistent
> gain on top of it: micro-F1 **0.575** (image) → **0.655** (text) → **0.668** (multimodal),
> with macro-F1 0.502 → 0.629 → **0.647** and mAP 0.501 → 0.696 → **0.707**. The fusion gain over
> the better unimodal system is larger than the seed-to-seed spread on all three metrics, and it
> is concentrated in the genres whose descriptions are vaguest.

## Overview

Digital storefronts label a game with a handful of genres, and those labels drive navigation,
recommendation and discovery. They are also noisy: publishers choose them, they mix real
gameplay descriptions with business descriptors such as *Indie* or *Free To Play*, and similar
games are routinely tagged differently.

Two signals describe what a game *is*, and neither is complete:

* a **screenshot** shows visual grammar — a cockpit and a track, a health bar and a weapon, an
  isometric map with selection boxes;
* a **description** states the designer's framing — *"explore a vast open world"*, *"manage
  supply lines"*, *"beat your friends' lap times"*.

A screenshot cannot tell you a game is turn-based; a description rarely tells you the art is
top-down pixel art. That asymmetry is what makes genre tagging a good test case for multimodal
learning, and GameSense measures whether the two signals are genuinely complementary.

The project is deliberately small and fully reproducible: every number and figure in the report
is regenerated by the commands in [Training](#training) and read from files on disk. Nothing is
transcribed by hand.

## Research questions

| | Question | Answered in |
|---|---|---|
| **Main** | Does combining vision and text beat either alone? | notebook §21 |
| **RQ1** | How well can genres be predicted from **screenshots only**? | notebook §20 |
| **RQ2** | How well from **descriptions only**? | notebook §20 |
| **RQ3** | Does **fusion** outperform both unimodal systems? | notebook §21.1 |
| **RQ4** | **Which genres** benefit most from fusion? | notebook §21.2 |
| **RQ5** | Which games and screenshots cause the **most errors**? | notebook §23 |
| **RQ6** | Does removing **titles and franchise names** from descriptions reduce text performance? | notebook §21.3, §23.4 |

RQ6 is treated as a first-class experiment, because it decides whether RQ2 and RQ3 mean
anything: a model that learned *"the word Skyrim implies RPG"* would look excellent and
generalise to nothing.

## Why multimodal learning?

Multi-label genre prediction is a good multimodal testbed because the modalities fail in
*different* places:

* **The image knows the look, not the rules.** Screenshots reveal art style, camera, HUD layout,
  vehicles, terrain and characters — but nothing about turn order, progression systems or
  narrative structure.
* **The text knows the pitch, not the look.** Store copy states goals and mechanics — but is
  written to sell, often omits the obvious, and is sometimes almost content-free.

If those failure modes are uncorrelated, fusion should beat both. If instead one modality
simply dominates, fusion buys redundancy rather than complementarity — and that is a finding
too. GameSense is set up so that either answer is reportable, and the negative one is not
hidden.

## Architecture

```
                                  GAME
                                    │
                   ┌────────────────┴────────────────┐
                   │                                 │
              SCREENSHOT                        DESCRIPTION
                   │                                 │
        resize 224² + ImageNet norm       WordPiece tokenizer (≤128)
                   │                                 │
                   ▼                                 ▼
        ResNet18  (frozen, ImageNet)      DistilBERT (frozen, 6 layers)
                   │                                 │
          global avg-pool → 512-d          masked mean-pool → 768-d
                   │                                 │
              L2 normalise                      L2 normalise
                   └────────────── concat ───────────┘
                                    │
                            1280-d fused vector
                                    │
                       fusion MLP  1280 → 512 → 256
                                    │
                             Linear → 8 logits
                                    │
                         sigmoid → 8 probabilities
```

Models A and B are the same picture with one branch removed and a `512→256→8` /
`768→256→8` head instead of the fusion MLP.

**Design choices, and why**

* **Sigmoid, not softmax.** Genres co-occur; a game can be Action *and* Adventure *and* RPG.
  Softmax forces the outputs to sum to 1, so the classes would compete — the wrong inductive
  bias. The loss is therefore `BCEWithLogitsLoss` over independent Bernoulli labels.
* **Frozen encoders by default.** With a few thousand training games, fine-tuning 78M
  parameters overfits fast and costs hours per epoch on CPU. Freezing keeps the comparison
  clean and — because a frozen encoder in `eval` mode is deterministic — lets the embeddings be
  cached once and reused for every epoch and every seed. Partial fine-tuning is available via
  `--unfreeze-stages` / `--unfreeze-layers` and reported as an auxiliary experiment.
* **Concatenation fusion, not cross-attention.** The question is *whether* fusion helps.
  Concatenation is the minimal fusion operator and keeps Model C architecturally comparable to
  A and B; cross-attention would confound "fusion helps" with "a bigger model helps".
* **L2-normalise before fusing.** Pooled ResNet and DistilBERT activations live on different
  scales; without normalisation one branch would dominate the first fusion layer for reasons of
  magnitude rather than content. An ablation tests whether it matters.
* **Masked mean pooling, not `[CLS]`.** DistilBERT has no next-sentence objective, so its
  `[CLS]` state is not a trained sentence summary.

## Dataset

[`FronkonGames/steam-games-dataset`](https://huggingface.co/datasets/FronkonGames/steam-games-dataset)
— **124,146** published Steam games, MIT licensed, built by an open-source scraper from
**Steam's own public Web API**.

| | |
|---|---|
| Raw snapshot | `data/raw/steam_games.parquet`, 192.0 MB, 41 columns (13 read) |
| Surviving the eligibility + content filters | **86,746** games (69.9 %) |
| Downloaded and used | **8,000** games → **16,000** screenshots |
| Split (game-level, seed 42) | 5,566 / 1,219 / 1,215 games → 11,132 / 2,438 / 2,430 samples |
| Label space | `Action, Adventure, Casual, RPG, Racing, Simulation, Sports, Strategy` |
| Mean genres per game | 2.21 |

The dataset stores screenshot **URLs**, not pixels, so images are fetched once from Valve's
public CDN and cached locally at ≤360 px. **No authentication, paywall, rate limit or
anti-scraping measure is bypassed anywhere in this project**; the downloader identifies itself,
pauses between requests and is resumable. Screenshots remain the copyright of their publishers,
are used locally for non-commercial academic research, and are git-ignored.

Full provenance, licensing, ethics and every measured statistic: **[`data/README.md`](data/README.md)**.

### Choosing the label space

Steam's `genres` field is not a taxonomy — its single most common value is *Indie*, a statement
about the publisher. The eight targets were selected from measured frequencies plus one
editorial rule: *keep gameplay genres with sufficient support; exclude anything describing the
business, the release state, the multiplayer mode or the software category.*

Two deviations from the original brief are worth flagging: Steam has **no `Shooter` genre**
(shooters are tagged `Action`), so `Casual` — a real, well-supported Steam gameplay genre —
takes its place; and `Massively Multiplayer` is excluded as a *mode* with too little support.

## Data processing

`python scripts/prepare_data.py` runs seven idempotent, resumable steps: acquire → clean →
subsample → expand → download → validate → split.

**Cleaning** removes, and *counts*, every unusable row: duplicate ids and descriptions, missing
or too-short (<15 words) or non-English descriptions, games with no target genre, games with
too few screenshots, and unreadable or near-duplicate images (64-bit average hash). The drop
accounting is asserted to balance (`rows_in − rows_out == Σ dropped`) and is pinned by a test.

**Text cleaning is Transformer-appropriate.** HTML, BBCode, URLs, e-mail addresses and
boiler-plate are removed; punctuation, capitalisation, numbers and word order are **kept**.
Applying the classical bag-of-words recipe here would destroy exactly the information a
pretrained WordPiece model was trained on.

**Adult content is screened out** by combining four signals — genre tags, `required_age ≥ 18`,
Steam's free-text `notes` advisory, and a keyword screen over title and description. Steam's
structured metadata alone is insufficient: only 139 of 124,146 rows carry a `Nudity`/`Sexual
Content` genre, while ~9.5 % of the catalogue is in fact adult material. This project renders
real screenshots into a report and a public app, so the screen is deliberately conservative.

### Two kinds of leakage, handled separately

1. **Textual leakage.** Store copy names the product and its genre: *"The Elder Scrolls V:
   Skyrim is an open-world **role-playing game**…"*. Three description variants are produced —
   `description_clean` (titles kept), `description_notitle` (titles, subtitles and initialisms
   replaced by *"this game"* — **used for all headline results**), and `description_masked`
   (genre vocabulary masked too). The gap between them is the RQ6 measurement.
2. **Structural leakage.** Each game contributes two screenshots **and one shared
   description**, so splitting on images would put the same description and near-identical
   pixels in both train and test. All splitting is over `app_id` groups, with **iterative
   stratification** (Sechidis et al., 2011) so rare genres stay proportionally represented. The
   guarantee is *checked* by `verify_no_group_leakage()`, stored in
   `data/splits/split_summary.json`, and asserted independently in the test suite.

## Models

| | Model A | Model B | Model C |
|---|---|---|---|
| Encoder | ResNet18 (ImageNet) | DistilBERT | both |
| Embedding | 512-d | 768-d | 1280-d fused |
| Head | 512→256→8 | 768→256→8 | 1280→512→256→8 |
| Loss | `BCEWithLogitsLoss` (+`pos_weight`) | same | same |
| Optimiser | AdamW, warmup + cosine | same | same |
| Trainable / total params | see notebook §14 | §15 | §16 |

An optional **BiLSTM** text baseline consumes the *same* WordPiece ids as DistilBERT, so the
comparison isolates the sequence encoder — pretrained self-attention versus
learned-from-scratch recurrence — rather than the tokenisation.

Checkpoints store only what training could change: a fully frozen pretrained encoder is
reproducible from its published weights, so checkpoints are a few MB rather than ~300 MB.

## Experiments

**Metrics.** Accuracy is *not* the headline. With 8 genres and ~2 positives per game, ~75 % of
all (game, genre) cells are negative, so element-wise accuracy rewards silence. GameSense
reports micro and macro precision / recall / F1, Hamming loss, subset accuracy, samples-F1 and
**mAP** (threshold-free). A large micro–macro gap is the signature of a model that learned the
head of the distribution and ignored the tail, which is why both are always shown.

**Thresholds.** A sigmoid output is a probability, not a decision. A grid from 0.20 to 0.80 is
searched **on the validation split only** and applied unchanged to test. Every results table is
reported twice — at a fixed 0.5 and at the validation-selected threshold — so the effect of that
choice is visible rather than hidden.

**Class imbalance.** Prevalence spans ~8.5 % (Racing) to ~46 % (Casual). `pos_weight` scales the
positive term of class *c* by `N⁻/N⁺` (computed from **training** data only, clipped at 10).
Whether it helps is treated as an experiment (`--class-weighting none`), not an assumption.

**Repeats.** The three headline systems are trained with seeds **42, 123, 2026** and reported as
mean ± standard deviation. Three runs indicate stability; they are *not* a confidence interval,
and the report says so.

**Ablations** (seed 42): titles left in (`text_leak`), genre words masked (`text_masked`),
BiLSTM instead of DistilBERT, no `pos_weight`, no L2 normalisation before fusion, and partial
fine-tuning of `ResNet18.layer4`.

## Results

All numbers below come from `results/metrics/`, written by the commands in
[Training](#training). Test split, decision threshold selected on **validation**, mean ±
standard deviation over seeds 42 / 123 / 2026.

### Headline comparison

| Model | Micro-F1 | Macro-F1 | Micro-P | Micro-R | mAP | Hamming ↓ | Subset acc. |
|---|---|---|---|---|---|---|---|
| Image only (ResNet18) | 0.5747 ± 0.0005 | 0.5023 ± 0.0034 | 0.4734 | 0.7312 | 0.5007 ± 0.0019 | 0.2979 | 0.0584 |
| Text only (DistilBERT) | 0.6547 ± 0.0040 | 0.6288 ± 0.0092 | 0.6214 | 0.6923 | 0.6956 ± 0.0053 | **0.2010** | **0.1780** |
| **Multimodal (fusion)** | **0.6676 ± 0.0066** | **0.6472 ± 0.0034** | 0.6065 | **0.7424** | **0.7071 ± 0.0035** | 0.2036 | 0.1727 |

**Fusion − best unimodal:** +0.0129 micro-F1, +0.0184 macro-F1, +0.0115 mAP. Each exceeds the
largest seed-to-seed standard deviation on that metric, so the ordering
image < text < multimodal is stable across the runs performed. With three seeds this is a
statement about *stability*, not a significance test, and none is claimed.

### Read the baselines first

| Input-blind baseline | Micro-F1 | Macro-F1 | mAP |
|---|---|---|---|
| Prevalence-matched random | 0.3494 | 0.2750 | — |
| **Constant prevalence vector, best threshold** | **0.5117** | 0.2816 | 0.2753 |

A predictor that ignores its input entirely scores **0.512 micro-F1** on this skewed label
distribution. That is why this project never reports micro-F1 alone: on the metrics a constant
predictor cannot fake, the image model reaches macro-F1 0.502 (vs 0.282) and mAP 0.501
(vs 0.275).

### Which genres benefit from fusion (RQ4)

Per-genre F1, seed 42, test split:

| Genre | Test support | Image | Text | Multimodal | Fusion − Text |
|---|---|---|---|---|---|
| Strategy | 560 | 0.457 | 0.487 | 0.563 | **+0.076** |
| Simulation | 624 | 0.500 | 0.571 | 0.637 | **+0.065** |
| Sports | 210 | 0.300 | 0.563 | 0.623 | **+0.060** |
| Action | 1078 | 0.660 | 0.716 | 0.743 | +0.028 |
| Adventure | 967 | 0.617 | 0.692 | 0.716 | +0.024 |
| Casual | 1084 | 0.644 | 0.679 | 0.689 | +0.010 |
| Racing | 201 | 0.432 | 0.686 | 0.678 | −0.009 |
| RPG | 484 | 0.396 | 0.564 | 0.545 | −0.019 |

Fusion helps most where the store copy is generic ("build", "manage", "compete") but the
screenshot is highly diagnostic, and slightly hurts the two genres whose descriptions are
already explicit. That is the pattern the multimodal hypothesis predicts, and it is the
strongest evidence here that the gain is real rather than an artefact of extra parameters.

Per sample, fusion produces a strictly better label set than the best single model on **28.2%**
of test games and a strictly worse one on **22.7%**.

### Ablations (seed 42, test split)

| Run | What changed | Micro-F1 | Macro-F1 | mAP |
|---|---|---|---|---|
| `text` | headline (titles removed) | 0.6503 | 0.6198 | 0.6960 |
| `text_leak` | titles left **in** the description | 0.6553 | 0.6301 | 0.7063 |
| `text_masked` | titles removed **and** genre words masked | 0.6372 | 0.5841 | 0.6506 |
| `text_bilstm` | BiLSTM instead of DistilBERT, same tokens | 0.6069 | 0.5755 | 0.6328 |
| `multimodal` | headline fusion | 0.6748 | 0.6490 | 0.7111 |
| `multimodal_nonorm` | no L2 normalisation before fusion | 0.6624 | 0.6390 | 0.7075 |
| `image` | headline frozen backbone | 0.5745 | 0.5007 | 0.5011 |
| `image_finetune` | `layer4` unfrozen + augmentation | 0.5772 | 0.5137 | 0.5023 |

**RQ6 — is the text model just reading the answer off the page? Largely, no.** Removing every
mention of the game's own title, subtitle and initialism costs about **0.005** micro-F1 —
comparable to the text model's own seed-to-seed spread. Masking explicit genre vocabulary
("role-playing", "racing", "turn-based", …) costs more, about **0.013** micro-F1 and 0.045 mAP,
but the model still reaches 0.637 with *both* titles and genre words gone. The text branch uses
distributed semantic evidence, not keyword lookup — which is what makes RQ2 and RQ3 meaningful.

**Pretraining is worth ~4 F1 points.** A BiLSTM trained from scratch on the *same* WordPiece
tokens reaches 0.607 against DistilBERT's 0.650 (and 0.633 vs 0.696 mAP), while overfitting
visibly — its training F1 passes 0.83 while validation stalls near 0.59.

**Partial fine-tuning bought almost nothing.** Unfreezing `ResNet18.layer4` (8.5M trainable
parameters instead of 134k) plus image augmentation moved the image model from 0.5745 to 0.5772
micro-F1 and 0.5007 to 0.5137 macro-F1, with mAP unchanged — for **36 minutes** of CPU training
against **21 seconds** for the frozen head. At 5,558 training games the pretrained features are
already close to what the vision branch can extract, which is the empirical justification for
the frozen-encoder design rather than a convenience argument.

### Class imbalance: the loss re-weighting did not earn its place

Both configurations were trained for all three systems over three seeds, and **the choice was
made on the validation split**:

| System | Validation micro-F1 (plain BCE) | Validation micro-F1 (`pos_weight`) | Test micro-F1 (plain BCE) | Test micro-F1 (`pos_weight`) |
|---|---|---|---|---|
| Image | **0.5733** | 0.5380 | **0.5747** | 0.5379 |
| Text | **0.6568** | 0.6360 | **0.6547** | 0.6426 |
| Multimodal | **0.6614** | 0.6452 | **0.6676** | 0.6539 |

Plain BCE plus a tuned threshold beat `pos_weight` for every system, so `class_weighting="none"`
is the configured default and the re-weighted variant is reported as the `*_posw` ablation. The
mechanism is visible in the outputs: `pos_weight` inflates rare-genre probabilities, threshold
search compensates by raising the threshold, and the threshold-free ranking (mAP) does not
improve. Two tools that both address imbalance turn out to be substitutes, not complements.

### Fusion leaves complementarity on the table

A per-sample **oracle** that always picked whichever unimodal model produced the better label
set would reach mean Jaccard **0.605**; the fused model reaches **0.548** and the better single
model 0.530. Roughly 0.057 Jaccard of genuine complementarity exists between the modalities and
concatenation fusion captures about a third of it — a concrete, quantified argument for the
cross-attention and gated-fusion mechanisms under [Future work](#future-work).

### Where the errors are (RQ5)

* **Single-genre games are hardest** (mean Jaccard 0.436 vs 0.60–0.62 for two- and
  three-genre games): the model assigns on average 1.48 spurious genres to a one-genre game.
* **Description length matters non-monotonically**: the 30–49 word band scores best (~0.56)
  while both very short (<20 words, 0.508) and very long (50+ words, 0.459) descriptions are
  worse — long store copy is marketing prose with a low density of genre evidence.
* **Screenshot brightness does *not* matter**: mean Jaccard varies only between 0.533 and 0.559
  across brightness quartiles. We expected dark screenshots to be harder; they are not, and that
  negative result is reported as one.
* **Grad-CAM shows the vision branch keying on scene rather than object** — for vehicle
  screenshots the evidence for *Racing* often sits on the road, cliff or sky rather than on the
  car, which is consistent with an ImageNet backbone and plausibly explains the weak Racing and
  Sports scores.

## Application

```bash
streamlit run app/streamlit_app.py
```

* upload a screenshot (JPG/JPEG/PNG) and/or type a description;
* choose **Image Only**, **Text Only** or **Multimodal** (default);
* read per-genre probability bars with the actual numbers and the predicted label set, plus the
  threshold used and where it came from;
* switch on **Model Comparison** to run all three models on the same input;
* inspect **Grad-CAM** for the vision branch, choosing the genre to explain.

The app performs **no** modelling of its own: all inference goes through
`gamesense.inference.GameSensePredictor`, which reuses the evaluation transform, the tokenizer
and the validation-selected threshold. That is what guarantees the demo cannot silently
disagree with the reported experiments. With no checkpoints present the page explains exactly
which commands to run instead of crashing, and every missing input, corrupt upload or Grad-CAM
failure is handled with a message rather than a traceback.


A fast smoke test of the whole path:

```bash
python scripts/prepare_data.py --max-games 200
python scripts/train_multimodal.py --max-samples 200 --epochs 2
```

Every script has `--help`. Device selection is automatic (`--device auto|cpu|cuda|mps`).

**Why it is affordable on a CPU.** With frozen encoders and no augmentation, an encoder forward
pass is a deterministic function of its input, so embeddings are extracted once and reused for
every epoch and every seed — mathematically the same optimisation problem, roughly two orders
of magnitude cheaper. The cache key hashes the encoder, image size, tokenizer length, pooling
mode and text column, and cached sample ids are validated against the current split, so a stale
cache can never be silently reused. Requesting `--unfreeze-stages`, `--unfreeze-layers` or
`--augment` disables caching automatically.

## Limitations

Stated plainly, because they bound how far the results can be read:

* **One storefront, weak labels.** Steam genres are publisher-chosen marketing metadata, so
  part of the error ceiling is label noise, not model failure.
* **A skewed subsample.** 8,000 of 86,746 eligible games, deliberately sampled to raise
  Racing/Sports support. Prevalence figures describe the *sample*, not Steam.
* **Content filtering changes the population.** ~10k games removed as adult material; the
  removed slice is non-random.
* **Two screenshots per game**, English descriptions only, and genre boundaries
  (*Action* vs *Adventure*) that are genuinely fuzzy even for humans.
* **Frozen encoders** in the headline results, so all three systems are likely below what full
  fine-tuning would reach — and the ordering could in principle change.
* **One fusion operator.** A small or negative result is evidence about concatenation fusion,
  not about multimodal learning in general.
* **Three seeds, no hyper-parameter search, no significance test.** The reported ± is a
  standard deviation over three runs and is labelled as such.
* **Threshold tuning adds a degree of freedom** fitted on ~1.2k validation games; some of the
  gain over 0.5 will not transfer.
* **Grad-CAM covers the vision branch only**, coarsely (7×7 upsampled), and is correlational.
* **CPU only** — which is why encoders are frozen, features are cached, and the fine-tuning
  experiment is small.

## Future work

Cross-attention and gated fusion · CLIP encoders so the two spaces are aligned before fusion ·
Vision Transformer backbones · full fine-tuning of both encoders · multiple screenshots per
game aggregated by attention · gameplay video and audio · Steam review sentiment as a third
modality · richer user-tag prediction · cross-storefront validation · zero-shot genre
