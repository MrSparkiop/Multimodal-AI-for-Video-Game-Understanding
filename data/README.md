# GameSense — data directory

*Author: Blagoy Hristov*

This directory holds every dataset artefact the project uses: the raw upstream snapshot, the
downloaded screenshots, the cleaned tables the models train on, and the train/validation/test
split files.

Nothing here is committed to git except this file (see [Directory layout](#1-directory-layout)).
Everything else is regenerated by one command:

```bash
python scripts/prepare_data.py
```

**Every number in this document was measured on 2026-08-21** by running the project's own
pipeline functions on the full 124,146-row snapshot. Section
[11](#11-provenance-of-the-numbers-in-this-file) says exactly which code produced which figure.
The machine-readable source of truth is `data/processed/cleaning_report.json`, written by every
run of `prepare_data.py`.

## 2. Data source and provenance

The metadata comes from the **Steam Games Dataset** on the Hugging Face Hub:

* **Repository:** `FronkonGames/steam-games-dataset` (`repo_type="dataset"`)
* **File used:** `data/train-00000-of-00001.parquet`
* **Licence:** MIT (stated in the dataset card's YAML front matter)
* **Upstream collection method:** the dataset card states it was built with the open-source
  [Steam-Games-Scraper](https://github.com/FronkonGames/Steam-Games-Scraper), which reads
  **Steam's own public Web API**, supplemented by SteamSpy. Only published games are
  included — no DLC, soundtracks, videos or episodes.
* **Retrieved:** 2026-08-21, saved locally as `data/raw/steam_games.parquet` (192.0 MB).

The dataset card advertises 138,964 games; the Parquet snapshot we retrieved contains
**124,146 rows**. We report what we measured rather than what the card claims.

**Screenshots are not in the dataset.** The `screenshots` column holds URLs on Valve's public
content-delivery network (`shared.akamai.steamstatic.com`). `prepare_data.py` fetches them once
and caches them locally at reduced resolution.

### Why this dataset

It is the only openly licensed source we found that provides, for the *same* title, all three
things this project needs: a natural-language description, curated genre labels, and multiple
real in-game screenshots. Alternatives were rejected for concrete reasons:

* **RAWG API** — requires a personal API key (verified: an unauthenticated request returns
  HTTP 401). Distributing a key with a student project is not acceptable, and working around
  the requirement would mean bypassing access control.
* **IGDB** — likewise requires OAuth credentials.
* **Image-only game datasets** — have no descriptions, so the multimodal question cannot be
  asked at all.

## 3. How to obtain the data

### Automatic (needs network access)

```bash
pip install -r requirements.txt
python scripts/prepare_data.py
```

Step 1 downloads the Parquet file via `huggingface_hub` if it is absent; step 5 downloads the
screenshots. **The whole script is resumable** — the Parquet file and every already-present
image are reused, so an interrupted run can simply be repeated.

### Manual (offline machine)

1. Download `data/train-00000-of-00001.parquet` from
   <https://huggingface.co/datasets/FronkonGames/steam-games-dataset>.
2. Save it as `data/raw/steam_games.parquet`.
3. Run `python scripts/prepare_data.py`.

If the file is missing and cannot be fetched, `download_raw_dataset()` raises a
`FileNotFoundError` whose message spells out exactly these steps.

The **metadata** stage then works fully offline. The **screenshot** stage still needs network
access; `--skip-download` runs the metadata pipeline alone (useful for inspecting the cleaning
funnel without fetching any image).

### Useful flags

```bash
python scripts/prepare_data.py --max-games 1000        # smaller, faster dataset
python scripts/prepare_data.py --skip-download         # metadata only
python scripts/prepare_data.py --shots-per-game 3      # more images per game
python scripts/prepare_data.py --workers 6             # gentler on the CDN
python scripts/prepare_data.py --force-download        # re-fetch the Parquet snapshot
python scripts/prepare_data.py --keep-orphan-images    # do not prune the image cache
```

## 4. Schema

### 4.1 Raw columns read

The Parquet file has 41 columns; `acquisition.RAW_COLUMNS` reads only these 13.

| Column | Type | Used for |
|---|---|---|
| `appID` | string | primary key → `app_id`, and the **grouping key for splitting** |
| `name` | string | title; also the input to title-leakage removal |
| `release_date` | string | context only |
| `short_description` | string | **the description the models read** (default) |
| `detailed_description` | string | alternative via `--description-field` |
| `genres` | list[string] | **the labels** |
| `categories` | list[string] | context only |
| `screenshots` | list[string] | screenshot URLs |
| `required_age` | int | adult-content screen |
| `notes` | string | Steam's free-text content advisory → adult-content screen |
| `header_image` | string | context only |
| `positive`, `negative` | int | review counts, context only |

The `tags` column exists in the schema but is **empty** in this snapshot (`list<null>`), so
Steam user tags are unavailable and the `genres` field carries all label information.

### 4.2 `data/processed/games.csv` — one row per game

| Column | Meaning |
|---|---|
| `app_id` | Steam application id (string) |
| `name` | game title |
| `description_raw` | the raw `short_description` |
| `description_clean` | cleaned text, **title still present** — the RQ6 "leaky" control |
| `description_notitle` | title/subtitle/initialism replaced by *"this game"* — **used for all headline results** |
| `description_masked` | as above **plus** explicit genre vocabulary replaced by `[GENRE]` |
| `description_word_count` | word count of `description_clean` |
| `genres` | pipe-joined canonical genres, e.g. `Action\|RPG` |
| `n_genres` | number of canonical genres |
| `n_screenshots` | screenshot URLs available upstream |
| `screenshot_urls` | tab-joined URLs |
| `y_action`, `y_adventure`, `y_casual`, `y_rpg`, `y_racing`, `y_simulation`, `y_sports`, `y_strategy` | the multi-hot labels (0/1) |

### 4.3 `data/processed/samples.csv` — one row per screenshot

| Column | Meaning |
|---|---|
| `sample_id` | `<app_id>_<shot_index>` |
| `app_id` | the parent game — **never split across train/val/test** |
| `shot_index` | 0-based index of the screenshot |
| `screenshot_url` | source URL |
| `image_path` | path relative to the project root, e.g. `data/images/12345_0.jpg` |
| `image_hash` | 64-bit average hash, used for near-duplicate detection |

Labels live only in `games.csv` and are joined on `app_id` at load time, so two screenshots of
one game can never disagree about that game's genres.

### 5.3 Two deviations from the original project brief

* **No "Shooter" class.** Steam has no `Shooter` genre — shooters are tagged `Action`. The
  brief's eight-genre example is therefore matched by substituting **`Casual`**, a genuine and
  well-supported Steam gameplay genre, for `Shooter`.
* **`Massively Multiplayer` excluded.** It describes a multiplayer *mode* rather than a genre,
  and with 2,563 raw games (2.1 %) it would land at roughly 200 positives in the sample — too
  few for a per-class F1 to mean much.

`config.EXCLUDED_GENRE_REASONS` carries these reasons in code, so the notebook renders the same
table from the same source.

### 6.3 Screening adult content

This project renders real screenshots into a written report and into a public Streamlit
application, so sexually explicit games must be excluded outright rather than merely
down-weighted.

**Steam's structured metadata is not sufficient on its own.** Only **139** of the 124,146 rows
carry a `Nudity` or `Sexual Content` **genre**, and only **169** have `required_age >= 18` —
yet roughly one row in ten is in fact adult material. `preprocessing.adult_content_mask()`
therefore combines four independent signals:

1. the `Nudity` / `Sexual Content` genre tags (139 rows);
2. `required_age >= 18` (169 rows);
3. Steam's free-text `notes` content advisory (22,868 rows have a non-empty `notes`; those
   matching patterns such as *nudity*, *sexual*, *adult content*, *uncensored* are flagged);
4. a keyword screen over the title and short description (stem terms such as *hentai*,
   *adult*, *uncensored*, *lewd*, *succubus*, plus whole-word terms such as *anal*, *18+*,
   where a prefix match would create false positives like *analysis*).

The union flags **11,812 rows (9.51 %)**; **10,258** of them reach step 9 of the funnel (the
rest were already removed by an earlier check).

The screen is deliberately conservative: it prefers dropping a borderline game to keeping an
explicit one. An independent audit of the resulting sample with a *broader* keyword
list found 28 residual matches, all of which were false positives of the audit list itself
(*Maiden*/*Maids* matching "maid", *stripes* matching "strip", mainstream non-explicit dating
simulators). No sexually explicit title was found in the final sample.

**This filter changes the population being studied**, and that is stated as a limitation rather
than hidden: the removed slice is non-random and weighted towards `Casual` and `Adventure`
visual novels, so the label distribution in [§5.1](#51-the-eight-target-genres) is shaped
partly by this decision. `prepare_data.py` also prunes the image cache at the end of each run,
so screenshots belonging to games a later, stricter filter excludes are deleted from disk.

### 6.4 Image-level validation

After download, every image is opened and reduced to a 64-bit average hash
(`preprocessing.image_average_hash`). Samples are dropped when the file is missing or cannot be
decoded, or when its hash duplicates one already seen. Duplicate screenshots would otherwise
inflate the effective dataset size and could pair identical pixels with two different games.
Measured on the run that produced the current dataset: **16,000** images requested,
**14,834** newly downloaded and 1,166 already cached, **0 failures**, 299.9 MB written in
1,284 s. Of the 16,000 stored images, **0 were unreadable** and **317 were near-duplicates**,
leaving **15,683** samples. Removing those cost 28 games their last usable screenshot, so
8,000 selected games became **7,972** in the final dataset. All counts are in
`cleaning_report.json → download / image_validation / reconciliation`.

## 7. Sampling

**86,746 eligible games is far more data than this project needs, and far more than it should
politely request.** At two screenshots per game the whole pool would mean ~173,000 image
requests to Valve's CDN. A subsample is drawn instead.

How to subsample is a genuine methodological choice:

* a **uniform random** subsample preserves Steam's real genre distribution, but at 4.0 %
  prevalence `Racing` would land at roughly 320 positives — too few for a stable per-class F1;
* a **fully balanced** subsample would destroy the class imbalance that the imbalance analysis
  is about.

`acquisition.select_games()` therefore uses a documented **hybrid**: 70 % of the budget
(5,600 games) is drawn uniformly at random, and 30 % (2,400 games) by a rarest-genre-first
round robin.

| Genre | Eligible pool (86,746) | Prevalence | Final dataset (7,972) | Prevalence | Change |
|---|---|---|---|---|---|
| Action | 39,429 | 45.45 % | 3,629 | 45.52 % | +0.07 pp |
| Adventure | 35,661 | 41.11 % | 3,260 | 40.89 % | −0.22 pp |
| Casual | 38,290 | 44.14 % | 3,672 | 46.06 % | +1.92 pp |
| RPG | 15,862 | 18.29 % | 1,618 | 20.30 % | +2.01 pp |
| **Racing** | 3,483 | 4.02 % | **677** | 8.49 % | **+4.47 pp** |
| Simulation | 18,674 | 21.53 % | 2,124 | 26.64 % | +5.11 pp |
| **Sports** | 4,026 | 4.64 % | **708** | 8.88 % | **+4.24 pp** |
| Strategy | 19,002 | 21.91 % | 1,909 | 23.95 % | +2.04 pp |

The rank order of the genres is preserved, but the two rarest classes are roughly doubled in
prevalence. **Consequence:** every prevalence figure reported in this project describes *the
sample*, not the Steam catalogue. Both distributions are stored in
`cleaning_report.json → sampling`, and the notebook plots them side by side so the effect of
this decision is visible rather than buried.

## 8. Splits

Splitting is performed over **`app_id` groups**, not over individual images, using iterative
stratification (Sechidis, Tsoumakas & Vlahavas, 2011) on the game-level label matrix.

| Split | Games | Samples |
|---|---|---|
| train | 5,558 | 10,934 |
| val | 1,214 | 2,384 |
| test | 1,200 | 2,365 |

Two reasons this matters:

* each game contributes **two screenshots and one shared description**, so an image-level split
  would place the identical description and a near-identical frame in both training and test
  data, and part of the reported score would be memorisation;
* multi-label random splitting can leave a rare genre with almost no validation positives,
  which makes macro-F1 fluctuate for reasons unrelated to the model.

The guarantee is **checked, not claimed**: `splitting.verify_no_group_leakage()` runs inside
`make_splits()`, its result is written to `data/splits/split_summary.json`, and
`tests/test_splitting.py` asserts the property independently.

## 9. Image storage

| | |
|---|---|
| Source | Valve public CDN (`shared.akamai.steamstatic.com`) |
| Stored resolution | long side ≤ 360 px (`DatasetConfig.stored_image_max_side`) |
| Format | JPEG, quality 88, `optimize=True` |
| Mean file size | **19.9 KB** (measured over 15,683 files) |
| Full cache (15,683 images) | **319.0 MB** |

Originals are ~1920×1080 at ~340 KB each; down-scaling on arrival keeps the local cache about
17× smaller with no effect on a model that resizes to 224². Storing at 360 px rather than 224 px
leaves room for the random-resized-crop augmentation.

Downloader behaviour (`DatasetConfig`): 8–10 worker threads, a descriptive `User-Agent`
(`GameSense-Academic-Research/1.0`), a 0.05 s pause per request per worker, 3 bounded retries
with exponential backoff, 10 s connect / 30 s read timeouts, atomic writes via a `.part`
temporary file, and skipping any file already on disk.

## 10. Ethics, licensing and acceptable use

* **Metadata licence.** MIT, as stated on the dataset card. Redistributable.
* **Screenshots.** These remain the copyright of the respective game developers and
  publishers. They are downloaded locally, at reduced resolution, for **non-commercial
  academic research only**, are **never redistributed** with this repository, and are excluded
  from version control via `.gitignore`. A small number of screenshots appear inside the
  research notebook as figures, which is a quotation for the purpose of academic criticism and
  review.
* **No access control is bypassed.** No authentication, paywall, login, rate limit, CAPTCHA or
  anti-scraping mechanism is circumvented anywhere in this project. The metadata comes from a
  published Parquet snapshot rather than from live scraping; the screenshots come from a public
  CDN that requires no credentials. The downloader is deliberately rate-limited and identifies
  itself.
* **RAWG / IGDB.** Both were rejected precisely *because* they require credentials
  ([§2](#2-data-source-and-provenance)). Nothing in this project attempts to work around that.
* **No personal data.** The pipeline reads only game metadata. No user accounts, reviews
  attributable to individuals, purchase histories or telemetry are involved, and nothing here
  identifies a person. Developer and publisher names are present in the upstream snapshot but
  are not read by `RAW_COLUMNS`.
* **Adult content.** Excluded by the four-signal screen in
  [§6.3](#63-screening-adult-content) before any screenshot is fetched for those games, and
  purged from the image cache if a previous, weaker filter had already downloaded them.
* **Weak labels.** Steam genres are publisher-chosen marketing metadata, not an expert
  taxonomy. They are treated as weak labels throughout, and the resulting ceiling on model
  performance is discussed in the notebook's limitations section.

| Section | Figures | Produced by |
|---|---|---|
| Summary, §2, §9 | row count, file size, column list, image sizes | `pyarrow.parquet` schema read + `pathlib` `stat()` on `data/raw/` and `data/images/` |
| §5.2 | the full 33-string genre frequency table | `collections.Counter` over the `genres` column of all 124,146 rows, classified with `preprocessing.normalize_genre` |

| §6.3 | per-signal adult-content counts | `adult_content_mask` plus the individual signals evaluated separately on all rows |
| §5.1, §7, §8 | sample support and prevalence, pool-vs-sample comparison, split sizes | `cleaning_report.json` (`sampling`, `splits`) and `data/processed/games.csv` |
| §6.3 audit | residual-match audit of the 8,000-game sample | an independent second-pass keyword screen with a deliberately broader term list than the pipeline uses |

**Reproducibility caveat.** The metadata pipeline is deterministic: four independent runs on
2026-08-21 all reported the same `124,146 → 86,746`, and `select_games(seed=42)` and
`make_splits(seed=42)` return identical selections and assignments on every run. The
**screenshot set** is not guaranteed stable over time — Valve can change a store page, so an
individual URL may 404 later. Failed downloads are counted in
`cleaning_report.json → download.errors_by_type` and their samples are dropped, which can move
the final sample count by a small amount between runs on different dates. In the run reported
here, 0 of 16,000 downloads failed.
